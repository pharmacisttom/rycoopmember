# ตรวจและแก้ระบบสมาชิก 11 ตุลาคม 2569

ระบบสมาชิกยังต้องทดสอบการเชื่อม PHP/MySQL จริงและ VPS ก่อนเปิดใช้งาน

แก้ Login ให้ใช้เลขบัตรประชาชนและรหัสเดิม ผ่าน CSRF/session ของ PHP ตรวจ profile เพื่อหา member id จริง ไม่ใช้ user id แทน member id ไม่ข้าม 2FA ไม่ใช้บัญชี demo แม้เป็น test mode

ทุกคำขอที่ยืนยันสมาชิกหรือเจ้าหน้าที่ตรวจบัญชีกับ /api/auth/me เพื่อให้บัญชีถูกระงับหรือสิทธิ์ถูกเปลี่ยนมีผล backend ยังคงเป็นผู้ตัดสินสิทธิ์ทุก API

CSRF ยอมรับเฉพาะ origin ที่กำหนด ไม่ยอมรับ subdomain อื่นหรือ localhost โดยอัตโนมัติ แก้ redirect วนจาก cookie หมดอายุ

รองรับ PHP session rotation และการเพิกถอน token ข้าม process ด้วยไฟล์ใน SESSION_STATE_DIR ข้อมูล PHP session ที่เก็บเข้ารหัส AES-GCM ต้องใช้ secret เดียวและ directory เดียวกันทุก worker ใช้ local persistent filesystem ของเครื่องเดียว ถ้า deploy หลายเครื่องต้องเปลี่ยนเป็น shared session service เช่น Redis ห้ามลบ state ระหว่าง release เพราะจะยกเลิกประวัติ revocation เก็บ directory นอก web root จำกัดสิทธิ์เจ้าของ process และสำรองอย่างปลอดภัย ต้องจัด housekeeping ลบไฟล์หมดอายุ

Dashboard ไม่แสดงยอดศูนย์แทนการเชื่อมต่อล้มเหลว ไม่อ้างว่าจ่ายแล้ว ไม่สร้างหมายเลขโอนเงิน และแยกยอดปันผล/เฉลี่ยคืน/สุทธิ ตามฐานข้อมูลจริง สมาชิกค้นหาได้ในหลังบ้านโดยใช้ API เดิม

บริการ Chat/Helpdesk/ผู้รับผลประโยชน์ที่ยังไม่มีการบันทึกจริงปิดการส่งและตอบ 503 บางหน้าเพิ่มเติมยังเป็นต้นแบบ ต้องพัฒนาหรือซ่อนก่อนเปิดใช้งาน

พบ routes PHP คำร้องเรียก methods ที่ไม่มี จึงเพิ่ม memberGetRequests และ memberSubmitProfileRequest ใน rycoopweb เชื่อม MemberRequestService ที่มีอยู่ ต้องนำไฟล์ PHP นี้ขึ้นพร้อมระบบสมาชิกและตรวจ migration 018_member_profile_requests ของเดิม สำรอง DB ก่อน migrate ห้าม Prisma migrate/db push/reset กับ DB จริง

## ก่อน deploy
- กำหนด PHP_BACKEND_URL ให้ถูกต้อง ไม่ชี้ production โดยอัตโนมัติ
- กำหนด TOMVIS_SESSION_SECRET แบบสุ่มอย่างน้อย 32 ตัว ห้ามใช้ค่าในตัวอย่าง
- กำหนด NEXT_PUBLIC_APP_URL=https://member.rayongcoop.tomvisolution.tech
- กำหนด PHP_SESSION_COOKIE_NAME ตาม config/security.php ของ backend
- กำหนด SESSION_STATE_DIR นอก web root ให้ Node เขียนได้
- npm ci, npm run typecheck, npm test, npm run build
- ตรวจ DNS/HTTPS/reverse proxy และ origin กับ request จริง
- ทดสอบสมาชิก 2 บัญชี บัญชีถูกระงับ เปลี่ยนสิทธิ์ หมดอายุ session คำร้องและการอนุมัติ พร้อมตรวจฐานข้อมูลก่อน/หลัง
- ไม่มีการ reset รหัสผ่านเดิม ไม่มีการ deploy production ในรอบตรวจนี้

## ข้อจำกัด
การทดสอบ contract ใช้ HTTP responses จำลองตามโค้ด PHP เพื่อหลีกเลี่ยงข้อมูลส่วนบุคคล ไม่ทดแทนการทดสอบกับ VPS ข้อมูลหุ้น/ฝาก/กู้/สวัสดิการยังไม่มี adapter ในโครงการนี้ ค่า placeholder ไม่ใช่การยืนยันว่าไม่มีเงิน

ตรวจ TypeScript ผ่าน และชุดทดสอบ 31 รายการผ่าน (เดิม 22 + contract/CSRF ใหม่ 9) ทดสอบโดยปิด Vitest cache และใช้ state directory แยกเฉพาะการทดสอบ

Production build ผ่าน ตรวจ PHP syntax ผ่าน และ integration คำร้องในฐานข้อมูลชั่วคราวผ่าน 8 ข้อ รวมการปลอม member_id การแยกสมาชิก 2 บัญชี และไม่เปลี่ยน profile ก่อนอนุมัติ ฐานข้อมูลทดสอบลบทิ้งหลังเสร็จ ไม่มีข้อมูลสมาชิกจริงในชุดทดสอบ

HTTP production smoke test ผ่าน 9 ข้อ: API ปฏิเสธ guest และ forged headers, หน้า login เปิดได้เมื่อ cookie หมดอายุ, POST ข้าม origin ถูกปฏิเสธ ปิดหน้า Chat/Helpdesk/เอกสาร/Statement/แจ้งเตือนตัวอย่าง และปรับเมนูสมาชิกให้แสดงบริการที่พร้อมเชื่อมข้อมูล

เพิ่มการทดสอบอนุมัติคำร้อง: บันทึกข้อมูลสมาชิกหลังอนุมัติเท่านั้น ไม่กระทบสมาชิกอื่น และบันทึกประวัติผู้อนุมัติผ่านทั้งหมด
